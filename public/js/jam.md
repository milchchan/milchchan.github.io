# Apricot キャラクター仕様

## 1. 基本構成

Apricot のキャラクターは、キャラクター情報とアニメーションを記述する JSON ファイル、会話の設定を記述するプロンプト、必要に応じた音声サンプル、表示に使う画像ファイルで構成します。

この JSON ファイルを **JAM (JSON Avatar Manifest）** と呼びます。

```text
Milch/
├── milch.json
├── prompt.txt
├── Milch-Prompt-001.wav
├── Milch-Prompt-002.wav
└── Images/
    ├── Milch-Idle.png
    └── Milch-Preview.png
```

- `milch.json`: キャラクター名、表示サイズ、使用するファイル、アニメーションを記述します。
- `prompt.txt`: キャラクターの性格、口調、AI が返す内容を記述します。
- `Milch-Prompt-001.wav`、`Milch-Prompt-002.wav`: キャラクターの声を伝えるための音声サンプルです。
- `Images/Milch-Idle.png`: キャラクターの表示に使う画像です。
- `Images/Milch-Preview.png`: 設定画面に表示するプレビュー画像です。

`milch.json` は次のように記述します。

```json
{
  "name": "Milch",
  "width": 320,
  "height": 480,
  "preview": "Images/Milch-Preview.png",
  "prompt": [
    "prompt.txt",
    "Milch-Prompt-001.wav",
    "Milch-Prompt-002.wav"
  ],
  "animations": [
    {
      "name": "Start",
      "repeats": 0,
      "frames": [
        {
          "url": "Images/Milch-Idle.png",
          "x": 0,
          "y": 0,
          "width": 320,
          "height": 480,
          "delay": 1,
          "z": 0
        }
      ]
    },
    {
      "name": "Emote",
      "repeats": 1,
      "frames": [
        {
          "url": "Images/Milch-Idle.png",
          "x": 0,
          "y": 0,
          "width": 320,
          "height": 480,
          "delay": 1,
          "z": 0
        }
      ]
    }
  ]
}
```

`Start` はキャラクター選択時に実行されます。`repeats: 0` は無限ループです。この例では同じ画像を表示し続け、会話後の `Emote` では同じ基本画像へ戻ります。

JSON ファイルは UTF-8 で保存し、拡張子を `.json` にします。1 個の JSON ファイルには 1 体のキャラクターを記述してください。画像やプロンプトなどのパスは、JSON ファイルがあるフォルダを基準とした相対パスで指定します。

## 2. 配置と読み込み

キャラクター一式を、iCloud Drive の Apricot フォルダ内にある専用サブフォルダへ置きます。JSON を Apricot フォルダ直下へ置かず、必ずキャラクターごとのフォルダを作ってください。

```text
iCloud Drive/
└── Apricot/
    └── Milch/
        ├── milch.json
        ├── prompt.txt
        ├── Milch-Prompt-001.wav
        ├── Milch-Prompt-002.wav
        └── Images/
            ├── Milch-Idle.png
            └── Milch-Preview.png
```

Apricot はサブフォルダを再帰的に検索します。読み込み後は、アプリの設定画面にある Characters からキャラクターを選択します。ファイルを変更した場合は、キャラクターを選び直すかアプリを再起動してください。

### 言語別ファイル

同じフォルダ内で、拡張子 `.json` の直前に言語コードを付けられます。たとえば、日本語版は `milch.ja.json`、台湾向け繁体字中国語版は `milch.zh-Hant.json` とします。

```text
milch.json          # 言語指定のない共通ファイル
milch.ja.json       # 日本語
milch.en.json       # 英語
milch.zh-Hant.json  # 繁体字中国語
```

選択順は、おおむね「端末の言語＋文字体系」→「端末の言語」→「言語コードの付かない共通ファイル」です。ファイル名には、小文字 2〜3 文字の言語コードと、任意の 4 文字の文字体系コード（例: `zh-Hant`）を指定できます。各言語ファイルは差分ではなく、必須項目をすべて持つ完全な JSON にしてください。

JSON 内に `language` がある場合は、ファイル名に付けた言語コードより優先して言語判定に使われます。

## 3. JSON 全体の項目

| キー | 型 | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| `$schema` | string | いいえ | なし | エディタ用の Schema パス。Apricot 自体は無視します。 |
| `name` | string | はい | — | 設定画面や会話で表示するキャラクター名。空文字は避けてください。 |
| `width` | number | はい | — | キャラクターキャンバスの幅。0 より大きい値を指定します。 |
| `height` | number | はい | — | キャラクターキャンバスの高さ。0 より大きい値を指定します。 |
| `x` | number | いいえ | `0` | ステージ内におけるキャンバス左上の X オフセット。 |
| `y` | number | いいえ | `0` | ステージ内におけるキャンバス左上の Y オフセット。 |
| `scale` | number | いいえ | `1` | キャラクター固有の座標倍率。通常は省略します。`0` だけは特殊値です。 |
| `language` | string | いいえ | 端末側の選択 | 会話と音声生成に使う言語コード。`ja`、`en`、台湾向けの `zh-Hant` などを指定します。 |
| `preview` | string | いいえ | なし | 設定画面に表示するプレビュー画像の相対パス。 |
| `prompt` | string または string の配列 | はい | — | キャラクター設定文と、任意の音声サンプル。詳細は次節を参照してください。 |
| `animations` | animation の配列 | はい | — | アニメーション／イベント定義。`Start` と `Emote` を含めます。 |

Apricot は未知のキーを無視することがありますが、タイプミスを検出できなくなるため使用しないでください。JSON 形式では `id` はサポートされず、指定しても無視されます。

`scale` が 0 より大きい場合、端末上のおおよその表示サイズは「キャンバスサイズ × `scale` ÷ 画面倍率」になります。`scale: 0` の場合は、座標の 1 単位を端末上の 1 ポイントとして扱う特殊動作になります。まずは既定値の `1` で確認し、必要な場合だけ調整してください。アプリ側の表示倍率設定は、この値とは別に適用されます。

## 4. プロンプトと音声サンプル

`prompt` が文字列の場合、その値は UTF-8 の `.txt` または `.md` ファイルへの相対パスです。

```json
{
  "prompt": "prompt.txt"
}
```

複数ファイルを配列で指定することもできます。

```json
{
  "prompt": [
    "prompt.txt",
    "Milch-Prompt-001.wav",
    "Milch-Prompt-002.wav"
  ]
}
```

- テキストのプロンプトはテキスト形式（`.txt`）とMarkdown形式（`.md`）に対応します。
- 複数の `.txt` または `.md` がある場合は、配列順に改行で連結され、1つのシステムプロンプトとして使われます。
- `.wav` はキャラクターの音声サンプルとして登録されます。1ファイルあたり約5〜10秒の、雑音やBGMが少ない明瞭な音声を推奨します。
- 配列内のその他の拡張子は無視されます。
- 文字列形式の `prompt` はテキストファイル専用です。音声も指定する場合は配列形式を使います。
- ファイルが存在しない、または UTF-8 として読めない場合、そのファイルは読み込まれません。

プロンプトには、キャラクターの名前、一人称、口調、性格、返答言語、避けるべき振る舞いなどを明記してください。

## 5. animation（アニメーション）オブジェクト

```json
{
  "name": "Emote",
  "state": "Happy",
  "repeats": 1,
  "frames": [],
  "animations": []
}
```

| キー | 型 | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| `name` | string | いいえ | なし | イベント名、または再利用するアニメーションの名前。イベントや呼び出し対象には指定してください。 |
| `state` | string | いいえ | なし | イベント実行時の値と照合する正規表現。 |
| `repeats` | integer | いいえ | `1` | フレーム列の反復回数。`0` は無限、`1` は 1 回です。 |
| `frames` | frame の配列 | いいえ | なし | このアニメーションで同時に再生を始める画像レイヤー群。 |
| `animations` | animation の配列 | いいえ | `[]` | このアニメーションから順に呼び出す、別のアニメーション。 |

`repeats` は 0 以上の整数にしてください。負数、小数、極端に大きい値はサポートされません。

### イベント名

次の名前は Apricot から自動的に呼び出されます。キャラクターとして表示・会話するため、`Start` と `Emote` は必須です。自然な待機動作のために `Idle` を推奨し、その他は必要な機能だけ定義します。

| `name` | 必須度 | 呼び出されるタイミング | `state` の条件と比較する値 |
| --- | --- | --- | --- |
| `Start` | 必須 | キャラクターの読み込み時 | 通常はなし |
| `Emote` | 必須 | AI が生成したメッセージと音声の後 | AI が選んだ感情名 |
| `Idle` | 推奨 | 操作や他のアニメーションがなく約 10 秒経過したとき | 通常はなし |
| `Stop` | 任意 | 別のキャラクターへ切り替える直前 | 通常はなし |
| `Tick` | 任意 | 読み込み時と、その後の毎分 | 日付と時刻を表す文字列（例: `2026-08-29T12:34:00+09:00`） |
| `DoubleTap` / `DoubleClick` | 任意 | キャラクター画像をダブルタップしたとき | タップされたフレームの `url` |
| `Alert` | 任意 | 新しい単語の取得後 | 通常はなし |
| `Weather` | 任意 | 位置情報から天気を更新したとき | 英語の天気コード（例: `Rain`） |
| `Star` | 任意 | スター数が変化したとき | スター数の文字列 |

`state` には、文字列の一致条件を表す正規表現を指定します。文字列全体を一致させたい場合は `^` と `$` を付けてください。状態に一致する同名定義がある場合はそれが優先され、一致するものがなければ `state` のない同名定義が使われます。

```json
{
  "name": "Weather",
  "state": "^((.*(Thunderstorms|Drizzle|Rain|Snow|Flurries))|Hail|SunShowers|StrongStorms|Sleet|Blizzard|Hurricane|TropicalStorm)$",
  "frames": [
    { "url": "Images/umbrella.png", "delay": 1, "z": 10 }
  ]
}
```

この例では、`Weather` イベントの `state` 項目に、傘をさす天気をまとめて指定しています。一致しない天気で傘を閉じる動作も必要な場合は、`state` を省略した別の `Weather` イベントを追加します。

### Emote

`Emote` は、AI が生成した会話メッセージと音声の後に呼び出される表情・感情リアクションです。利用できる感情名は、キャラクター JSON だけで決まるものではなく、`prompt.txt` がAIへ指示する出力形式の `states` オブジェクトで定義します。

推奨するAI応答のうち、`Emote` に関係する部分は次のとおりです。

```json
{
  "content": "<会話の文章>",
  "states": {
    "Angry": 0.0,
    "Confused": 0.0,
    "Happy": 0.0,
    "Relaxed": 0.0,
    "Sad": 0.0,
    "Shy": 0.0,
    "Surprised": 0.0
  }
}
```

各値は `0.0`〜`1.0` の感情スコアです。Apricot は `states` の中から最も高い正のスコアを持つキーを選び、そのキー名と `state` が一致する `Emote` イベントを再生します。すべて 0、`states` がない、または対応する定義がない場合に備えて、`state` を省略した `Emote` イベントも用意してください。

標準の感情名は次の 7 種類です。

| `state` | 想定する表情 |
| --- | --- |
| `Angry` | 怒り |
| `Confused` | 困惑 |
| `Happy` | 笑顔・喜び |
| `Relaxed` | 落ち着いた通常表情 |
| `Sad` | 悲しみ |
| `Shy` | 照れ |
| `Surprised` | 驚き |

同じ `name: "Emote"` の定義を感情ごとに用意します。キャラクター JSON の `state` は、`prompt.txt` の `states` に書いたキーと大文字・小文字を含めて一致させてください。

```json
{
  "animations": [
    {
      "name": "Emote",
      "state": "Happy",
      "repeats": 1,
      "frames": [
        {
          "url": "Images/Milch-Idle.png",
          "delay": 1,
          "z": 0
        }
      ]
    },
    {
      "name": "Emote",
      "repeats": 1,
      "frames": [
        {
          "url": "Images/Milch-Idle.png",
          "delay": 1,
          "z": 0
        }
      ]
    }
  ]
}
```

## 6. frame（フレーム）オブジェクト

| キー | 型 | 必須 | 既定値 | 説明 |
| --- | --- | --- | --- | --- |
| `url` | string | いいえ | なし | 画像ファイルの相対パス。 |
| `x` | number | いいえ | `0` | キャンバス左上からの X 座標。右方向が正です。 |
| `y` | number | いいえ | `0` | キャンバス左上からの Y 座標。下方向が正です。 |
| `width` | number | いいえ | `0` | 描画幅。0 の扱いは下記を参照してください。 |
| `height` | number | いいえ | `0` | 描画高さ。0 の扱いは下記を参照してください。 |
| `opacity` | number | いいえ | `1` | 不透明度。`0`〜`1` を指定します。 |
| `delay` | number | はい | — | このフレームを表示する秒数。`0.01` より大きい値を指定してください。 |
| `z` | integer | いいえ | `0` | レイヤー順。小さい値が背面、大きい値が前面です。 |
| `type` | string | いいえ | なし | 着せ替えなど、切り替え可能な外観グループ名。 |

画像サイズは次のように決まります。

- `width` と `height` がともに 0: 画像本来のピクセルサイズ
- `width` だけが 0: `height` と画像の縦横比から幅を計算
- `height` だけが 0: `width` と画像の縦横比から高さを計算
- 両方が 0 より大きい: 指定サイズへ描画

`url` のないフレームも使用できます。たとえば、同じ `(z, type)` のレイヤーを一定時間透明にしたい場合は `opacity: 0` のフレームを置けます。

省略された `delay` は 0 として扱われますが、0 秒のフレームや合計時間が 0 の無限ループは正しく再生できません。この仕様と JSON Schema では `delay` を必須としています。

### フレームのグルーピング規則

1 個の animation オブジェクトにある `frames` 配列では、`z` と `type` の組み合わせが同じフレームが 1 本の時系列になります。

- 同じ `(z, type)`: 配列に現れた順に再生
- 異なる `(z, type)`: 同時に再生される別レイヤー
- `repeats`: 作られた各レイヤーのフレーム列に適用
- アニメーション全体の所要時間: 有限レイヤーのうち最も長い再生時間

次の例では、体を `z: 0` に表示したまま、`z: 1` の目だけを開閉します。

```json
{
  "name": "Idle",
  "repeats": 1,
  "frames": [
    {
      "url": "Images/body.png",
      "x": 0,
      "y": 0,
      "width": 320,
      "height": 480,
      "delay": 3.2,
      "z": 0
    },
    {
      "url": "Images/eyes-open.png",
      "x": 96,
      "y": 92,
      "width": 128,
      "height": 32,
      "delay": 3,
      "z": 1
    },
    {
      "url": "Images/eyes-closed.png",
      "x": 96,
      "y": 92,
      "width": 128,
      "height": 32,
      "delay": 0.2,
      "z": 1
    }
  ]
}
```

`type` を指定したレイヤーは、設定画面から切り替えられる外観候補として登録されます。同じ `type` を衣服の複数パーツへ指定すると、それらをまとめて切り替えられます。通常のキャラクター画像には `type` を付けないでください。

負の `z` は背景レイヤーとして別扱いされます。通常のキャラクター作成では 0 以上を使用してください。

## 7. アニメーションの再利用と実績解除

同じアニメーションを複数のイベントから使う場合は、名前を付けて一度だけ定義し、別の場所からその名前で呼び出せます。

以下の例は、JSON 全体にある `animations` 配列だけを抜粋しています。

```json
{
  "animations": [
    {
      "name": "Start",
      "animations": [
        { "name": "BasePose" }
      ]
    },
    {
      "name": "BasePose",
      "repeats": 0,
      "frames": [
        { "url": "Images/Milch-Idle.png", "delay": 1, "z": 0 }
      ]
    }
  ]
}
```

この例では、`frames` を持つ `BasePose` が再利用するアニメーションの定義です。`Start` イベント内の `animations` 配列にある `{ "name": "BasePose" }` は、その定義を名前で呼び出しています。

- `frames` または中身のある `animations` を持つオブジェクト: 再利用するアニメーションの定義
- `name` だけを持つオブジェクト: 同じ名前で定義したアニメーションの呼び出し
- 呼び出す名前は大文字・小文字を含めて定義と一致させる
- 再利用する定義は、JSON 全体の `animations` 配列へ置くと管理しやすい

### 実績解除

実績は、`Star` イベントの中に名前付きアニメーションを置いて定義します。`Star` イベントの `state` 項目には、実績を解除するスター数の範囲を正規表現で指定します。

以下の例も、JSON 全体にある `animations` 配列だけを抜粋しています。

```json
{
  "animations": [
    {
      "name": "Star",
      "state": "^[1-9]$",
      "animations": [
        {
          "name": "水着",
          "repeats": 1,
          "frames": [
            {
              "url": "Images/Milch-Idle.png",
              "delay": 1,
              "z": 0
            }
          ]
        },
        {
          "name": "水着"
        }
      ]
    }
  ]
}
```

この例の `^[1-9]$` は、スター数が 1〜9 のときに一致します。条件に初めて一致したときに実績「水着」が解除され、同じ名前で定義したアニメーションが再生されます。

作成手順は次のとおりです。

1. JSON 全体の `animations` 配列に、`name` が `Star` のイベントを追加する
2. その `Star` イベントの `state` 項目に、解除対象となるスター数の範囲を書く
3. その `Star` イベント内の `animations` 配列に、`frames` を持つ名前付きアニメーションを置く
4. その後ろに、同じ `name` だけを持つ呼び出しを置く
5. 名前付きアニメーションの `name` を、ユーザーに表示したい実績名にする

実績ごとに別の `Star` イベントを作成できます。

| 条件に一致するスター数 | `Star` イベントの `state` に書く値 |
| --- | --- |
| 1〜9 | `^[1-9]$` |
| 10〜49 | `^[1-4][0-9]$` |
| 50以上 | `^([5-9][0-9]\|[1-9][0-9]{2,})$` |

表の 3 条件を別々の `Star` イベントとして定義すると、スター数に応じた段階別の実績を作れます。たとえば 5〜9 だけを対象にする場合は `^[5-9]$` と書きます。`^` は文字列の先頭、`$` は末尾を表すため、`15` や `50` はこの条件に一致しません。

表で使っている `[1-9]` は 1〜9 の数字 1 文字、`[0-9]` は 0〜9 の数字 1 文字を表します。`|` は左右どちらか、`{2,}` は直前の条件が 2 回以上続くことを表します。

## 8. 画像ファイル

- 透過を使える PNG を推奨します。
- `url` と `preview` は JSON ファイルからの相対パスです。
- 絶対パスとネットワーク URL は使用できません。
- `image.png` に対して `image@2x.png` または `image@3x.png` が同じフォルダにある場合、端末の画面倍率に合うファイルが優先されます。JSON には常に `image.png` と書きます。
- ファイル名の大文字・小文字を一致させてください。

## 9. バリデーション

JSON の構文だけを確認するには、Python 3 を利用できる環境で次を実行します。この方法は Windows、macOS、Linux で利用できます。

```sh
python -m json.tool milch.json
```

環境によってコマンド名が異なる場合は、`python` を `python3` または Windows の `py` に置き換えてください。正常な場合は整形された JSON が表示され、構文エラーがある場合は行番号と内容が表示されます。

対応エディタでは、JSON の一番外側に置く `$schema` を、ダウンロードした [`apricot.schema.json`](apricot.schema.json) へ向けると、必須項目、型、範囲、タイプミスを編集時に検出できます。Schema をキャラクター JSON と同じフォルダへ置いた場合は、`"$schema": "apricot.schema.json"` と指定できます。Schema ファイルそのものは Apricot への配布に含めなくても構いません。

Apricot は読み込みエラーを画面へ表示せず、無効なファイルや項目を読み飛ばすことがあります。表示されない場合は次を順に確認してください。

1. JSON が Apricot フォルダ直下ではなく、サブフォルダ内にある
2. `name`、`width`、`height`、`prompt`、`animations` が存在し、型が正しい
3. 必須イベントの `Start` と `Emote` があり、有効なフレームを参照している
4. 画像、プロンプト、音声の相対パスと大文字・小文字が一致している
5. 全フレームの `delay` が 0 より大きい
6. コメント、末尾カンマ、`NaN` など標準 JSON でない記法を使っていない

## 10. `prompt.txt` の書き方

`prompt.txt` は、キャラクターの人格とAI応答の形式を定義する UTF-8 のテキストファイルです。曖昧さを減らすため、次の順で書くことを推奨します。

1. AIが演じるキャラクターと役割
2. 必ず守る口調・性格・禁止事項
3. キャラクターの背景設定
4. 代表的な発言サンプル
5. AIが返すJSONの出力形式

### 記述例

次のテンプレートをコピーし、キャラクターに合わせて角括弧内を置き換えてください。

```text
あなたはキャラクター「ミルヒ」のロールプレイを行います。
以下の設定と制約を守り、会話の流れに合った自然な返答を生成してください。

# 制約条件
- 名前はミルヒです
- 一人称は「ミルヒ」です
- 明るく元気で、相手の好きなものを否定しません
- 柔らかく、かわいらしい日本語で話します
- 敬語や丁寧語は使いません
- 通常の会話文は100字以内にします
- 会話に合った感情スコアを設定します

# 背景設定
[キャラクターの過去、友人、現在の状況、好きなものなどを記載]

# 発言サンプル
こんにちは。ミルヒだよ。
[口調が分かる短い発言を複数記載]

# 出力形式
応答は説明、前置き、Markdown、コードフェンスを含めず、必ず有効なJSONオブジェクトだけを出力してください。

- likabilityは、ユーザーへの好感度を0.0から1.0で表します
- contentは、キャラクターが実際に話す文章です
- termsは、contentに含まれる固有性の高い名詞です
- statesは、各感情の強さを0.0から1.0で表します
- statesでは会話に最も合う感情を1つ選び、その値が他の感情より高くなるようにします
- choicesは、ユーザーが次に選べる自然な返答候補です
- choicesのurlは、contentに関連する正確なWebページがある場合だけ指定し、それ以外はnullにします
- memoryは、今後の会話でも役立つ情報だけを簡潔なMarkdownで記録します。記録する内容がなければ空文字にします

次のキーを省略せず、この形で出力してください。
{
  "likability": 0.5,
  "content": "ミルヒもいっしょにやってみたいな！",
  "terms": [],
  "states": {
    "Angry": 0.0,
    "Confused": 0.0,
    "Happy": 1.0,
    "Relaxed": 0.2,
    "Sad": 0.0,
    "Shy": 0.0,
    "Surprised": 0.0
  },
  "choices": [
    {
      "text": "いっしょにやってみよう",
      "url": null
    }
  ],
  "memory": ""
}
```

### 出力フィールド

| キー | 型 | 説明 |
| --- | --- | --- |
| `likability` | number | 好感度。`0.0`〜`1.0`。 |
| `content` | string | キャラクターが表示する会話文。 |
| `terms` | array | 会話文中の特徴的な名詞。単独なら文字列、修飾語を分ける場合は `[修飾語, 名詞]` の配列。該当なしなら `[]`。 |
| `states` | object | `Emote` の選択に使う感情スコア。7種類すべてを毎回含めます。 |
| `choices` | array | 次の会話候補。各要素は `text` と、文字列または `null` の `url` を持ちます。 |
| `memory` | string | 今後も必要な記憶をまとめたMarkdown。記憶がなければ空文字。 |

### `states` と `Emote` の対応

`states` のキーは、キャラクター JSON にある `Emote` イベントの `state` 項目と、大文字・小文字を含めて一致させます。標準では次の7キーをすべて出力してください。

```json
{
  "Angry": 0.0,
  "Confused": 0.0,
  "Happy": 1.0,
  "Relaxed": 0.2,
  "Sad": 0.0,
  "Shy": 0.0,
  "Surprised": 0.0
}
```

最高値が同じ感情を複数作ると選択結果が一定しないことがあるため、最も適切な感情が1つだけ最高になるようプロンプトで指示します。すべての値が 0 の場合は、`state` を省略した `Emote` イベントが使われます。
